# 项目前端行为准则

先读 `AGENTS.md`、SPEC 中相关 UI/事件/安全章节和当前实现。用户最新明确要求优先；本 Skill 不放宽 SPEC 的证据、覆盖、权限与安全要求。

## 1. 先证明必要，否则不引入

**凡有理由认为不需要引入的元素或信息，都不引入。**

新增任何文字、图标、按钮、卡片、标签、指标、面板、装饰、动画、依赖或状态前，先回答：“缺少它，哪个明确任务会无法完成？”只接受以下必要性依据：

- 用户当前明确要求；
- SPEC 的 MUST 或现有公共契约要求；
- 核心工作流不可替代的步骤；
- 证据核查、安全、隐私、失败恢复或许可披露义务。

“以后可能有用”“页面太空”“其他产品也有”“数据已经返回”“看起来更专业”均不是理由。无法证明必要时，删除而不是保留，不新增而不是占位。

先删减，再优化，最后才考虑新增。相同信息只保留一个最佳位置；终态隐藏不可用操作；低频诊断按需展开。不得用新的面板解决旧面板过多的问题。

## 2. 保留已确认的信息架构

除非用户或 SPEC 变更，沿用以下结构，不另起平行设计：

- **首页**：标题、检索模式、输入/文件入口、数据源、发送和必要的模拟数据说明。不要英文装饰语、流程步骤条、重复宣传语或高级设置堆叠。
- **对话与榜单**：2026-11-17 用户明确批准多轮对话，覆盖旧“不新增聊天”的限制。桌面左侧连续对话、右侧独立榜单 artifact；手机按需切换。综合结论只进聊天，默认简短，不在榜单顶部重复展示。用户追问旧结果可直接回答，不强制重搜；历史榜单不改评分、不被新轮次抹去。仅保留必要的“检索结果”、状态及错误，不重复整段 Query/Claim、徽章、快照/诊断面板或能力横幅。
- **多次检索**：只有 Agent 实际创建多个 query 时才显示切换 Pill。每个 query 独立保存 Claim、排名、Worker、SSE、快照与证据，禁止跨 query 混排或覆盖旧结果；用户手动查看旧查询时不自动跳走。
- **项目与数据源申请**：登录后在现有历史侧栏选择项目；新会话默认「其它」，搜索块仍按整个视口居中。项目设置复用现有表单；左下入口只在有未处理或未读接入状态时出现。窄屏不盖住输入，审批状态只读服务端，失败不显示为已接入。
- **数据源**：当前榜单内按需展开“数据源 x/n”、真实来源完成数与每库最新 Worker 卡；不再占独立第三栏，不抢对话空间。来源完成不表示中央排序或父 Agent 完成；无实际检索不造空榜。不要状态汇总、重复覆盖块、截止提示、事件列表或面板套卡片。
- **右侧结果区**：一行一篇，保留组内名次、分数、题名、书目信息、推荐理由、目标 Claim、来源、版本、复制和证据入口。利用真实可用宽度，不为制造紧凑感另设任意最大宽度。
- **证据详情**：对照目标 Claim、推荐理由、原文和定位。无公开原文时如实说明，不伪造链接或跳转成功。

## 3. 只展示真实进度

禁止往返、闪烁、脉冲等没有数据含义的“看起来在工作”进度条。

- 从 API/SSE 的 Worker 状态和计数推导进度，不猜测总数、百分比、剩余时间或成功率。
- 左侧进度只表示已完成数据源数/本次计划库数，不包含中央 LLM 排序或父 Agent 的后续决策。失败、超时、取消不得计为完成；新 attempt 开始后按新 attempt 的真实状态计算，不用旧完成状态维持假单调。
- 每库仅展示最新 attempt，保持本次选库顺序，不把重试拆成多张卡。同一 attempt 的迟到状态与低计数不得覆盖新状态。
- 来源子 Agent 卡片只显示库名、Worker 状态与真实“已发现/已提交”计数；不把提交当核验，不显示无意义的“推荐 0”，不推测它正在检索、思考还是补查。旧逐篇路径使用“候选/已处理”，同样不暗示全文核验。
- 中央排序等待/失败、结果部分完成及父 Agent 尚在运行，按实际榜单与运行状态在结果标题旁简短说明；没有可靠细节就不展示细节，不重建一个推测 Workflow。
- 不以静态满格冒充整次检索完成，不以动画代替真实状态。断线、部分覆盖和失败必须可见且可诊断。

## 4. 保持克制的视觉与动效

- 复用当前纸白、墨色和青绿色令牌，不引入第二套品牌色、外部字体、图标库或 UI 框架。
- 使用共享圆角令牌。内部圆角按“外层半径－内边距”对齐；检索区采用全胶囊形，支持时启用 `corner-shape: squircle`，不支持时回退大圆角。
- 圆角服务于组件层级，不为不同组件随意挑选数值。避免卡片套卡片和无意义边框、阴影、渐变。
- 动效只用于必要的状态理解，并尊重 `prefers-reduced-motion`。首屏不使用遮挡内容的入场动画，进度不使用循环动画。
- 同时检查信息密度与阅读舒适度：既防无效留白，也防为了填满而增加无关信息。

## 5. 不改变权威数据与能力边界

- 沿用原生 HTML/CSS/ES modules 和现有文件职责；新增依赖必须先证明现有方案不能满足需求并记录收益与回退条件。
- 分数、排名、分组、覆盖、快照和 Worker 状态以服务端为准。前端不得发明跨库换算、第二套排序或第二份数据源注册表。新候选链路仅按服务端 `llm_rank` 展示最终名次，基础分与服务端同池 `rank_delta` 分开；等待/失败不得冒充最终排名。真实库请求不得附带演示用的物种、温室/田间或方法 scope。
- 不可信标题、摘要、证据和模型文本只用 `textContent` 或文本节点，不拼接 HTML。
- 关键词与 Abstract 首轮走真实 `POST /api/v1/agent/runs`；后续消息走服务端会话，Agent 自主决定是否检索。全文按真实能力开关上传/解析后发送实际 manuscript_id，保留页段与OCR警告，未ready禁发；失败不假装成功。上传与模型发送前一处简明披露足够，匿名实例不用于私稿；不把整篇原文发给在线检索来源。
- 「全文」模式内是首页唯一的文件选择入口；关键词和 Abstract 模式不放独立上传按钮。安全检查暂不可用时如实提示并可重查，已上传但状态失联时重查同一稿件，不自动重传。复制入口按需展开服务端书目格式；原始题录不冒充 CSL，格式切换不触发模型。新检索在后台准备有依据的建议，「引用建议」只读已排队/生成的内容；查看不启动模型。无全文/证据不足/撤稿明确拒绝，不把生成 ready 称全文认证或自动采用，不编造书目、页码、理由或模板兜底。具体状态与例外见 FND-059。
- 保持 SSE 幂等、断线重建、按 `result_id` 原位更新和快照不可变，不为视觉重写牺牲正确性。排名、分数或理由变化也不替换整张候选卡；无变化时不得重复 append 已在正确位置的节点。只移动真正变更位置的节点，保留摘要/嵌套详情、焦点、文本选择和视口阅读锚点；不以淡入动画表现流式更新，不保留旧池排名冒充当前终排。

## 6. 用真实交互验收，而非自我描述

先测试删减和状态逻辑，再用内置浏览器检查真实页面：

1. 验证模式切换、数据源选择、文件选择与禁发边界。
2. 分别观察运行中与终态：快库先出、慢库后插入，同一 attempt 状态不倒退，重试按真实状态重新计数，失败不计完成；来源完成但排序仍等待时不能伪装全部完成。模拟多次工具调用，验证 query 切换不串结果；无工具调用时展示实际答复并隐藏来源区。
3. 验证动态排名、复制和可用的证据/来源入口；快照不可变性由后端与状态测试覆盖，不为了测试而在主界面新增诊断入口。
4. 检查桌面宽屏和手机窄屏的实际截图：空间利用、溢出、长文本省略、圆角对齐、按钮遮挡和滚动位置。
5. 运行与变更相关的项目测试、静态检查及 `tools/smoke.py`；广泛变更执行 README 中完整验证链。

DOM 文本检查不能替代视觉验收。截图或浏览器不可用时应明确报告未验证项，不宣称“已通过视觉复核”。

## 7. 交付前逐项否决

- 是否还有无法证明必要的元素、信息、样式或依赖？
- 是否有重复状态、重复操作、装饰性文案或只为填空的模块？
- 是否存在假进度、假上传、假链接、假引文或假完成？
- 是否每库一卡、来源/排序/父 Agent 生命周期分清、同 attempt 不倒退、新 attempt 不假完成、终态操作消失、诊断按需可达？
- 是否充分利用屏幕且无横向溢出、嵌套卡片和圆角失配？
- 是否保留服务端权威、SSE 恢复、快照冻结和文本安全？
- 是否完成真实浏览器验证并如实记录边界？

最终说明重点列出：删除了什么、必要新增是什么、实际验证了哪些交互与截图、仍有哪些能力未实现。不要为了总结而新增用户未要求的文档或文件。
