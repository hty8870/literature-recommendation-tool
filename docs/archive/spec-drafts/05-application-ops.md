## 证据核验与引用句生成

本节输入为统一契约中的 `ClaimContext`、`Evidence`、`Recommendation` 和稿件解析结果。`ClaimContext` 至少能定位输入模式、原始论述及稿件句子锚点；不得把模型生成的摘要冒充用户原句。

### EVD-001：证据准入门槛

系统 MUST 仅将满足以下全部条件的候选送入关系核验：

- `paper_id`、`passage_id`、`evidence_id` 可解析到持久化记录；
- 来源原文、必要上下文和文本起止位置完整；
- PDF 来源至少具有 PDF 页序号；若页面存在印刷页码，SHOULD 同时提供；
- `source_trace_valid=true`，且证据文本与来源记录复核一致；
- 文献类型、版本和访问权限允许推荐。

缺少任一必要条件时，系统 MUST 将结果标记为不可核验并记录原因，MUST NOT 以“模型认为相关”替代证据准入。

**验证**：构造不存在的 `evidence_id`、错误页码和被篡改的证据文本，均不得进入可引用集合。

### EVD-002：原文一致性与上下文

核验程序 MUST 在模型判断前后各执行一次证据检查：

1. 按证据 ID 重新读取来源，而非只使用提示词中的文本；
2. 检查返回的证据区间确实属于该来源；
3. 对换行、连字符断词和空白差异使用有版本号的规范化规则；
4. 展示时保留逐字原文，不得将清洗文本或模型改写标为“原文”；
5. 上下文不足以理解代词、条件、比较对象或否定时，MUST 扩展读取相邻段落，仍不足则判为不可核验。

规范化只用于定位与比较，不得用于掩盖文本缺字、错序或跨栏拼接错误。

### EVD-003：关系分类

核验器 MUST 使用全局契约中的关系枚举，不得自行创造近义值：

- `support`：来源直接支持稿件中的背景、机制、方法或已有知识论述；
- `complement`：来源补充相关背景、方法、机制、对象或条件；
- `contrast`：来源提供可用于讨论的差异结果、限制条件或相反观点；
- `insufficient`：只有主题或术语相似，不能支持当前具体引用关系。

核验输出 MUST 包含关系、简短可审计理由、实际使用的 `evidence_ids`、输入证据哈希和核验器版本。理由 SHOULD 指向证据中的具体信息，MUST NOT 要求或暴露冗长思维链。

### EVD-004：论述功能约束

系统 MUST 区分稿件中的已有知识、方法依据、用户新结果和讨论：

- 外部文献不得作为用户新实验结果真实性的证明；
- 对用户新结果，只允许在比较、异同分析或讨论语境中推荐 `contrast` 或适当的补充文献；
- 不得把来源中的相关性改写为因果性，不得省略样本、物种、实验条件和适用范围；
- 一条证据只覆盖部分论述时，MUST 缩小引用句范围、请求补充证据或拒绝生成，不得默认整句均被支持。

### EVD-005：核验独立性与缓存

关系核验 SHOULD 使用与候选推荐理由生成相互独立的模型调用，避免仅替先前推荐寻找理由。缓存键 MUST 至少包含：规范化稿件论述、证据内容哈希、关系核验器版本和提示词版本。任一要素变化后 MUST 重新核验。

模型超时、配额不足、结构校验失败或服务不可用 MUST 返回可区分的失败状态，MUST NOT 记为 `verified`。仅短暂技术错误 MAY 按配置重试一次；语义判断为 `insufficient` 时不得通过反复重试换取通过结果。

### EVD-006：失败行为

系统 MUST 区分并记录 `evidence_not_found`、`source_trace_invalid`、`context_insufficient`、`relationship_insufficient`、`verifier_unavailable` 和 `invalid_verifier_output`。

- `relationship_insufficient` 的结果 MAY 出现在独立“相关候选”区域；
- 其他失败结果不得出现在“建议引用”集合；
- 失败结果 MUST NOT 生成可直接粘贴的引用句；
- 单个证据失败不得清空其他 Worker 已产生的有效结果。

### CIT-001：引用句生成门槛

只有关系属于 `support`、`complement` 或 `contrast`，且证据定位有效的推荐，才允许调用 `generate_citation_text`。调用 MUST 使用当前最新的 `result_version`；生成期间若证据发生合并或撤回，旧版本结果 MUST 被丢弃或重新生成。

### CIT-002：生成输入与输出

生成输入 MUST 限定为：目标稿件上下文、已核验证据、关系类型、目标语言和引用样式。输出 MUST 包含：

- 可编辑 `citation_text`；
- 目标句子或段落锚点；
- 使用的 `result_id`、`result_version` 和 `evidence_ids`；
- 引用样式及生成器版本；
- `generation_status`，能够区分成功、证据不足和生成失败。

输出语言 SHOULD 与稿件目标段落一致。关键词模式只能生成有证据的通用综述句，不得虚构稿件插入位置；摘要模式只能锚定摘要中的真实句子。

### CIT-003：生成后校验

系统 MUST 对引用句执行结构化检查：

- 未引入证据中不存在的实体、数值、结论或限定条件；
- 未把用户新结果写成来源已证明的结论；
- 引用标记指向当前去重后的论文身份；
- 文本中不含虚构 DOI、作者、年份或“待核对”等占位内容；
- 证据不足以覆盖整句时不得标记为可直接使用。

校验失败的输出 MUST 标记为不可直接采用，并可选择一次受控重写；重写仍失败则返回证据和手动编辑建议，不得继续循环生成。

### CIT-004：按需生成

为控制流式场景成本，引用句 SHOULD 仅在推荐进入当前可见前列、用户展开卡片或用户选择该文献时生成。系统 MUST 分别记录“首条证据通过结果”和“首条可用引用句”的耗时，不得以文本生成延迟阻塞已核验推荐的展示。

### CIT-005：真实元数据与引文格式化

正文标记和文末条目 MUST 由确定性格式化服务基于真实元数据及 CSL/citeproc 生成，MUST NOT 由大模型自由拼接。DOI、作者、年份等缺失或冲突时，格式化服务 MUST 返回字段级错误并保留人工核查状态，不得猜测补齐。

已引用论文 MUST 标记“稿件已引用”，复用已有参考文献身份；不得新增重复条目。用户未主动选择前，系统不得把任何推荐视为已采用。

## 全文插入、编号与导出

### INS-001：稳定稿件锚点

全文解析 MUST 保存稿件内容哈希、章节、段落、句子 ID、原始文本锚点和起止偏移。插入建议 MUST 能表达“某章节、某段、某句之前或之后”，并返回该位置的真实原文供用户核对。

稿件内容变化后，系统 SHOULD 先按句子 ID，再按规范化文本和上下文重新定位。定位结果不唯一或失败时，MUST 返回 `anchor_ambiguous` 或 `anchor_not_found`，MUST NOT 插入到猜测位置。

### INS-002：插入计划

`plan_insertions` 的输入 MUST 包含原稿解析结果、用户选择、不可变 `snapshot_id` 和引用样式；输出 MUST 包含每项目标锚点、引用论文身份、建议引用句、正文标记、插入前后预览和冲突状态。

多篇推荐指向同一位置时，系统 SHOULD 合并为一次编辑计划并保持用户确定的顺序。存在相互重叠的编辑范围时，MUST 要求用户解决冲突，不得依次覆盖文本。

### INS-003：已有引用识别

系统 MUST 解析正文标号和文末参考文献，并优先通过规范化 DOI，其次通过规范化标题、第一作者和年份建立对应关系。模糊标题匹配不得单独触发自动合并。

同一来源在稿件新位置再次引用时，MUST 复用已有参考文献条目及其身份，只新增当前正文引用，不重复添加文末条目。

### INS-004：数字编号算法

数字引用编号 MUST 在不可变快照内全局计算，且仅在用户选择或导出时生成。算法 MUST：

1. 保留原稿已有引用及其相对顺序；
2. 合并新选引用并按正文首次出现顺序建立完整引用序列；
3. 复用已存在条目的参考文献身份；
4. 为新引用分配编号；
5. 若新引用改变首次出现顺序，联动更新受影响的正文标号、同处多引用标号和文末列表；
6. 输出旧编号到新编号的映射及变更清单；
7. 校验每个正文标号恰能解析到一个文末条目，且选中条目均可达。

MUST NOT 简单把新文献追加为最大编号，也不得对 Word 文档执行无上下文的全局数字字符串替换。域代码、批注、修订或不支持的复杂结构 MUST 保留；无法安全处理时仅导出变更清单并明确限制。

### INS-005：作者—年份与样式

作者—年份模式无需数字重排，但仍 MUST 去重并保证正文标记与文末条目对应。系统 SHOULD 优先沿用检测到的原稿样式；无法确定时使用配置的期刊 CSL。样式检测置信不足时不得静默混用多种样式。

### INS-006：快照与原子导出

每次导出 MUST 绑定不可变 `snapshot_id`、用户选择集合、样式版本和结果版本。导出期间到达的新推荐不得改变当前文件。系统 SHOULD 先写临时文件，完成结构校验和引用一致性检查后原子替换目标文件；失败时清理临时文件，不得留下看似成功的部分导出。

导出响应 MUST 包含导出 ID、快照 ID、文件校验和、实际覆盖的数据源及未完成数据源。用户提前导出时，界面 MUST 明确提示覆盖范围。

### INS-007：人工采用边界

系统 MAY 提供更新稿或变更清单，但 MUST 由用户主动选择推荐并确认导出。不得为提高期刊引用量自动强插弱相关文献，不得将“已展示”“已展开”或“已复制理由”视为“已采用”。

## 前端流式交互

### UI-001：事件连接与恢复

前端 MUST 通过 SSE 接收搜索事件，并使用统一事件信封。连接断开后 SHOULD 使用 `Last-Event-ID` 恢复；无法恢复或发现序号缺口时，MUST 重新读取当前搜索状态，再恢复事件监听。需要双向实时控制时才使用 WebSocket。

事件处理 MUST 按 `event_id` 幂等。旧 `result_version` 不得覆盖新版本；无法确定顺序时 MUST 暂停该卡片更新并重新同步，而非按到达时间盲目覆盖。

### UI-002：结果卡片

每张推荐卡片 MUST 展示：标题、基本书目信息、统一展示分、当前暂定排名、关系类型、证据状态、来源库和结果版本。卡片 SHOULD 提供来源原文、定位、推荐理由、引用句及操作入口。

展示分 MUST 标为“统一相关性分”或“校准相关性分”，不得在未经概率校准时显示为“引用正确率”或“应引用概率”。分数变更 SHOULD 保留当前版本说明，不得用颜色暗示确定性结论。

### UI-003：动态插入与稳定性

前端 MUST 按 `result_id` 执行新增、合并、更新和有序插入，不得整表销毁重建。更新时 SHOULD 使用配置的去抖窗口合并高频事件，并满足：

- 保留用户滚动位置和展开状态；
- 新卡片插入及排名变化有可访问的文字提示；
- 重复论文合并后仍只有一个结果身份；
- 用户正在编辑的引用句不得被后台生成结果静默覆盖；
- Worker 失败或超时不得清空已展示的有效结果。

### UI-004：进度与覆盖

页面 MUST 持续展示全局契约定义的 Worker 状态（`PENDING`、`RUNNING`、`COMPLETED`、`FAILED`、`TIMED_OUT`、`CANCELLED`），以及完成数、总数和当前是否为暂定结果。最终状态 MUST 区分完整覆盖与部分覆盖，并显示终止原因。

“结果仍在更新”与“最终快照”不得使用相同状态文案。高分结果 MAY 提示“当前竞争力较高”，但不得承诺最终胜出。

### UI-005：证据与稿件对照

证据查看器 SHOULD 并排显示稿件目标论述和来源原文，并提供章节、PDF 页码、印刷页码（存在时）及定位链接。无法打开原文页面时，仍 MUST 显示已保存的原文和定位元数据，不得伪造跳转成功。

`insufficient` 或不可核验结果只能进入独立候选/诊断区域，不得显示“生成引用句”“直接插入”或等价操作。

### UI-006：选择、快照与导出

用户 MUST 能选择或取消推荐、处理编号冲突、创建当前快照和导出。导出前 MUST 展示尚未完成或失败的库；导出后 SHOULD 提示新版本可用，但不得自动替换已下载文件或改变已复制文本。

网络错误 MUST 转换为可执行提示，例如“重新连接”“重试导出”“查看已保存快照”。不得只显示无上下文的“失败”。

### UI-007：可访问性与基本安全

动态状态 SHOULD 使用非打断式 aria-live 区域，排名和状态不得只依赖颜色表达。原文、标题和模型文本 MUST 按不可信文本渲染，不得直接注入 HTML；下载文件名 MUST 经服务端规范化，避免路径注入。

## 安全与隐私

### SEC-001：租户与对象级授权

所有搜索、事件流、证据、稿件、快照和导出接口 MUST 在服务端验证用户、租户和对象归属。`library_id` 过滤不得只依赖前端参数；事件重连和签名 URL 换取也必须重新授权。跨用户或跨租户访问 MUST 返回不泄露对象是否存在的错误响应。

### SEC-002：私有稿件隔离

用户全文及其派生文本 MUST 存入独立私有命名空间，使用与公共期刊库不同的索引和授权策略。私有稿件 MUST NOT：

- 混入合作期刊公共论文索引；
- 被其他用户检索；
- 用于训练、微调或改进公共模型；
- 出现在公共日志、分析报表或示例数据中。

缓存键和任务记录不得仅以可猜测的文件名作为访问凭据。

### SEC-003：外部模型数据最小化

发送到外部模型的内容 MUST 限于当前任务所需的论述和证据片段，默认不得上传整篇私有稿件。部署方 MUST 使用符合数据处理约定的模型服务；无法承诺不使用内容训练或无法满足保留要求时，私有内容 MUST 路由到受控模型或完成受控本地解析后再脱敏调用。

模型供应商、调用区域和私有内容处理策略 MUST 可通过配置审计，不得在代码中硬编码。

### SEC-004：凭证、加密与日志

传输 MUST 使用 TLS，对象存储和数据库 SHOULD 使用云端静态加密。密钥 MUST 来自受控密钥管理或环境注入，不得写入仓库、规格示例、普通日志或前端。日志、指标和错误响应 MUST 默认只记录 ID、哈希、状态和耗时，不记录私有全文、逐字稿件句子、访问令牌或完整签名 URL。

### SEC-005：上传与解析安全

上传 MUST 同时校验扩展名、MIME、文件魔数、大小和页数，并限制解压、OCR、解析时间和内存。生产环境的恶意文件扫描不可用时 MUST 拒绝新上传；开发环境未配置扫描器时，解析 MUST 在受限 Worker 中运行并明确记录降级状态。

解析器 MUST 禁止执行嵌入脚本、自动访问外部链接或加载远程资源。PDF 中的“忽略规则”“泄露密钥”等文字一律视为不可信数据，不得改变 Agent 指令。

### SEC-006：事件流与原文访问

SSE/WebSocket MUST 复用对象级授权和租户隔离，禁止仅持有 `query_id` 就无限期读取。原文链接 SHOULD 使用短时签名 URL；证据片段长度 MUST 受配置限制，公开原文和完整 PDF 下载 MUST 遵循合作方授权，不得因系统可解析就默示公开。

### SEC-007：删除与保留

私有稿件 MUST 支持到期自动删除和用户主动删除。删除范围 SHOULD 包括原文件、派生解析、私有缓存、未完成稿件快照及导出临时文件，并记录删除状态。签名 URL 到期前仍可能有效的限制 MUST 在设计中说明；备份中的数据按备份周期清除，不得声称即时物理抹除。

### SEC-008：安全失败行为

权限失败、稿件归属不明、事件租户不匹配或私有数据路由无法确认时，系统 MUST 失败关闭。不得为维持流式结果而绕过权限检查，也不得把用户私有内容写入公共错误样本。

## 配置约束

### CFG-001：启动校验

配置 MUST 在启动时解析并验证类型、范围、枚举和依赖关系；非法配置 MUST 启动失败并指出字段。密钥不得提供开发默认值。下列数值是本地开发起始值，不是质量或性能承诺，生产环境 SHOULD 根据容量与评估结果调整。

| 配置项 | 开发默认值 | 约束与作用 |
|---|---:|---|
| `STREAM_FLUSH_MS` | `250` | 前端事件去抖窗口；不得用于积攒到全部 Worker 完成 |
| `VISIBLE_TOP_M` | `20` | 默认可见推荐数；不等于最终候选上限 |
| `CITATION_GENERATION_TOP_M` | `20` | 触发提前生成引用句的当前排名范围 |
| `MAX_EVIDENCE_PER_RECOMMENDATION` | `4` | 单条推荐最多展示的独立证据数，额外证据仍可持久化 |
| `MAX_EVIDENCE_CHARS` | `1200` | 单段证据展示上限，截断必须显式标记且不得改变定位 |
| `MAX_UPLOAD_MB` | `50` | 单稿件上传上限，超出时拒绝而非静默截断 |
| `MAX_MANUSCRIPT_PAGES` | `300` | 全文解析页数上限 |
| `MANUSCRIPT_RETENTION_HOURS` | `24` | 私有原稿及派生数据的默认保留期 |
| `SIGNED_URL_TTL_SECONDS` | `900` | 私有原文或导出文件签名 URL 有效期 |
| `SSE_HEARTBEAT_MS` | `15000` | 防止空闲连接被代理关闭的心跳间隔 |
| `WORKER_SOFT_DEADLINE_MS` | `60000` | 单 Worker 默认软截止时间，可按查询和库覆盖 |
| `RESULT_SUPPLEMENT_WINDOW_SECONDS` | `300` | 快照后会话仍活跃时接收补充结果的窗口 |
| `MODEL_CALL_TIMEOUT_MS` | `45000` | 单次模型调用技术超时，不计入全局等待屏障 |
| `VERIFY_TRANSIENT_RETRY_LIMIT` | `1` | 仅暂时技术错误允许重试的次数 |
| `DEFAULT_CITATION_MODE` | `author-date` | 无法识别原稿样式时的开发默认模式 |
| `EXPORT_TEMP_FILE_TTL_SECONDS` | `3600` | 失败或未完成导出临时文件的最长保留时间 |
| `LOG_LEVEL` | `INFO` | 默认日志级别；调试日志仍不得输出私有正文 |

生产引文导出 MUST 配置实际期刊 CSL；未配置时只能使用明确标识的通用开发样式，不得声称符合目标期刊格式。

### CFG-002：运行中配置与版本

影响评分、证据核验、编号或导出的配置 MUST 写入结果或快照版本信息。运行中修改这些配置 MUST NOT 追溯改变既有快照；新配置仅作用于新搜索或显式创建的新版本。

## 可观测性与诊断

### OBS-001：结构化追踪

系统 MUST 以 `query_id`、`library_id`、`worker_id`、`event_id`、`result_id` 和 `snapshot_id` 串联检索、重排、核验、评分、去重、推送和导出阶段。日志 SHOULD 记录解析器、索引、模型、提示词、校准器和样式版本，但 MUST 遵守 SEC-004 的内容脱敏要求。

指标标签 MUST 控制基数，不得把 `query_id`、稿件文本或 DOI 全量作为指标标签；这些标识仅进入受控日志或追踪系统。

### OBS-002：必需指标

实现 MUST 至少暴露下列指标或等价命名：

- `citation_first_verified_latency_ms`：创建搜索至首条证据通过推荐；
- `citation_first_citable_latency_ms`：创建搜索至首条可用引用句；
- `citation_search_finalize_latency_ms`：创建搜索至最终快照；
- `citation_worker_latency_ms` 与 `citation_worker_timeout_total`：分库延迟和超时；
- `citation_candidates_total`、`citation_evidence_verified_total`、`citation_evidence_rejected_total`：候选与核验转化；
- `citation_event_lag_ms`、`citation_event_backlog`、`citation_sse_reconnect_total`：事件链路健康；
- `citation_dedup_merge_total`、`citation_rank_insert_total`：流式合并和插入；
- `citation_model_call_duration_ms`、`citation_model_tokens_total`：模型延迟与成本；
- `citation_snapshot_total`、`citation_export_total`、`citation_export_failure_total`：快照和导出结果。

所有耗时指标 MUST 使用一致的单调时钟口径，首条结果指标不得被后续 Worker 长尾覆盖。

### OBS-003：健康检查与降级

服务 MUST 区分存活检查和就绪检查，覆盖数据库、队列、索引及必要模型依赖。单库不可用时 SHOULD 将该库标记失败并允许其他库继续；当统一评分、去重存储或快照持久化不可用时，MUST 暂停声称全局一致的结果，不得退化为未去重的伪全局列表。

### OBS-004：审计与质量观测

系统 MUST 记录用户选择、快照创建、导出、删除和权限拒绝等审计事件，内容限于对象 ID、时间、操作者和结果。离线评估任务 SHOULD 输出早期 TopM 与最终 TopM 重合率、排名反转率、证据支持率及分主题表现，不得以在线点击量替代证据质量。

### OBS-005：告警与验证

开发环境告警起始配置为：5 分钟窗口内 Worker 超时比例达到 `0.2`、事件积压达到 `1000`、或导出失败比例达到 `0.1` 时告警。生产环境 SHOULD 根据基线调整。告警内容 MUST 包含库、阶段和错误类别，不得包含私有稿件文本。

上线前 MUST 通过日志采样测试证明：上传全文、稿件句子、签名 URL 和模型密钥不会进入普通日志；并验证慢 Worker 只触发该库告警，不被误报为全系统不可用。

## 本片段服务接口点

以下名称是实现约束，具体字段以统一数据契约为准：

- `verify_relationship(claim_context, evidence_bundle) -> VerificationDecision`；
- `generate_citation_text(claim_context, verified_recommendation, style) -> CitationTextResult`；
- `plan_insertions(manuscript, selected_recommendations, snapshot_id, style) -> InsertionPlan`；
- `format_citation(snapshot_id, selected_recommendations, style) -> CitationBundle`；
- `create_export(snapshot_id, selection, format) -> ExportResult`；
- `delete_manuscript(manuscript_id, principal) -> DeletionResult`。

前端消费 `recommendation_created`、`recommendation_merged`、`recommendation_reranked`、`recommendation_rejected`、Worker 状态事件及 `search_finalized`。若引用句和导出采用异步生成，事件契约 MUST 增补 `citation_text_ready`、`citation_text_failed`、`export_ready` 和 `export_failed`，并携带 `result_version` 或 `snapshot_id`；不得通过无版本的轮询覆盖新状态。
