## 验收测试与质量门槛

### 质量工程要求

- **QAL-001｜测试确定性**：验收测试 MUST 使用固定文献夹具、确定性假模型、可控时钟和可控 Worker 完成闩锁。不得依赖外部模型、真实第三方库或任意 `sleep` 时长判断流式正确性。
- **QAL-002｜分层验证**：每个实现任务 MUST 同时交付与其改动对应的单元测试、契约测试或集成测试。仅验证模块能导入、服务能启动或页面能渲染，不构成任务完成。
- **QAL-003｜端到端验收**：M2 起 MUST 通过真实 API、事件流和前端状态验证用户场景；不得只调用内部函数模拟“端到端通过”。
- **QAL-004｜失败可见**：测试失败 MUST 保留失败事件、状态快照和必要日志。不得通过删除断言、跳过测试、放宽证据规则、捕获后忽略异常或提高超时时间来制造通过。
- **QAL-005｜追踪性**：每个 MUST 级产品需求 MUST 至少映射到一个 `AT-*` 验收场景和一个 `T*` 实现任务；若某需求不可自动验证，MUST 明确人工检查步骤和证据。
- **QAL-006｜回归门禁**：契约、权限、证据、快照和引文一致性测试 MUST 阻断交付。性能和质量评估 MUST 与已版本化基线比较，不得只报告平均值而隐藏长尾和失败样本。

### 标准测试夹具

实现 Agent MUST 建立以下可复用夹具；夹具中的论文、分数和证据均为测试数据，不得伪装成真实文献进入生产库。

| 夹具 | 必须包含的内容 | 主要用途 |
|---|---|---|
| `paper_set_basic` | 至少 6 篇有真实测试用 DOI 形式的研究论文，含标题、作者、摘要、正文、页码和坐标 | 检索、证据、引文与去重 |
| `paper_set_versions` | 同一论文的不同 DOI 写法、原始论文、更正声明、撤稿及无 DOI 记录 | 版本治理与重复判定 |
| `manuscript_numeric` | 三个章节、已有 `[1]`～`[3]`、对应文末条目和稳定句子锚点 | 插入位置与编号联动 |
| `worker_gate` | A/B/C 三个可控 Worker，可分别暂停、释放、失败、超时和发送迟到事件 | 流式、截止与取消 |
| `score_fixtures` | 同口径评分器、异构本地评分器、固定统一重排器、来源校准器及版本 | 跨库评分与版本兼容 |
| `event_trace` | 正常、重复、乱序、迟到、版本冲突和断线重放事件序列 | 幂等、重放和状态收敛 |
| `evidence_cases` | `support`、`complement`、`contrast`、`insufficient`、错页、错引文和篡改文本 | 证据门槛与拒答 |
| `tenant_cases` | 两个用户、两个期刊库、一份私有稿件和一份恶意提示注入 PDF | 权限、隔离与提示注入 |

## 验收场景

### 检索、Worker 与流式处理

| 验收 ID | 场景与操作 | MUST 满足的断言 |
|---|---|---|
| **AT-RET-001** | 查询同时包含罕见基因名和无语义重叠的同义表达 | 精确术语候选可由关键词路召回，改写候选可由向量路召回；合并结果取并集，保留来源和库内排名。 |
| **AT-RET-002** | 构造一个大而低相关的库和一个小而高相关的库 | 动态 TopN 不按固定库比例分配；大库不能仅凭规模耗尽预算；保留配置的探索配额。 |
| **AT-RET-003** | 检查论文正文、参考文献列表、页眉页脚和更正声明索引 | 参考文献及重复模板不进入主要正文索引；文献类型和更正关系符合入库策略。 |
| **AT-STR-001** | 暂停 B，释放 A 的一条证据通过推荐；在 B 仍未释放时读取 API、SSE 和前端 | A 的结果已可见，B 显示运行中；不得存在等待 B 完成的全局屏障；首个可见结果已经通过证据门槛。 |
| **AT-STR-002** | A 已产生结果后释放分数更高的 B 结果 | B 按统一展示分插入正确位置；旧结果身份不复制；前端收到插入或排名变化事件。 |
| **AT-STR-003** | 一个 Worker 超时，另一个正常完成，随后形成快照 | 正常结果不丢失；快照明确记录完成、超时和未覆盖范围；不得把部分覆盖标成全库完整。 |
| **AT-STR-004** | 结果不足与结果充分两种情况下触发停止策略 | 不足时允许补充检索或等待；充分时可取消低预期收益任务；已取消 Worker 的迟到事件不能改变原快照。 |
| **AT-STR-005** | Worker 在单库处理途中产生多条合格推荐 | 推荐可逐条或小批发出，不要求本库全部完成后才发送；事件顺序与 Worker 状态一致。 |

### 跨库评分、去重与动态排名

| 验收 ID | 场景与操作 | MUST 满足的断言 |
|---|---|---|
| **AT-SCR-001** | 两个同口径库对相同查询、文本和统一重排器评分 | 展示分使用相同算法和 `score_version`；相同输入得到相同展示分；原始检索信息仍可诊断。 |
| **AT-SCR-002** | 两个库分别返回量纲不同的本地分，但提供相同候选文本和证据 | 统一重排后展示分一致；本地原始分只作为来源数据保留，不直接跨库比较。 |
| **AT-SCR-003** | 外部库不能统一重排，分别使用适用、失效和样本不足的校准器 | 适用校准器可转换；失效或样本不足时执行明确回退和标记，不得宣称精确可比或伪称概率。 |
| **AT-SCR-004** | 已有一组结果后加入更高分和更低分结果 | 已有结果的展示分不因当前批次最小值或最大值变化；仅按规则插入或合并，禁止在线批次 min-max 归一化。 |
| **AT-SCR-005** | 同一结果使用两个评分版本到达 | 系统重新转换为当前版本，或明确分组标记不可比；不得无说明混排。 |
| **AT-DED-001** | 多库返回带 `doi:`、DOI URL、大小写和尾标点差异的同一论文 | 规范化后合并为一个 `result_id`；来源集合和证据集合均保留，列表不重复。 |
| **AT-DED-002** | 两篇论文仅标题近似，DOI、作者或年份冲突 | 不得仅凭模糊标题自动合并；保留独立结果或进入明确复核状态。 |
| **AT-DED-003** | 重复论文的后到证据提高其排序竞争力 | 只重算该合并结果的展示分并增加 `result_version`；其他结果分数不被无意义重算。 |
| **AT-SCR-006** | 对同一最终事件集采用多种 Worker 到达顺序并重放 | 同一评分、去重和版本配置下，最终快照的结果身份、分数和稳定排序一致。 |

### 证据、引用句与引文格式

| 验收 ID | 场景与操作 | MUST 满足的断言 |
|---|---|---|
| **AT-EVD-001** | 分别输入支持、补充、对比和仅主题相似的证据 | 前三类按语义进入相应关系；`insufficient` 不进入可引用集合，也不生成可粘贴引用句。 |
| **AT-EVD-002** | 返回不存在于来源的引文、错误页码、无效坐标或失效段落 ID | `source_trace_valid=false`；结果不得绕过证据门槛，失败原因可诊断。 |
| **AT-EVD-003** | 稿件句子报告用户自己的新实验结果 | 不得用外部论文证明该新结果；只允许在语义成立时提供对比或讨论建议。 |
| **AT-EVD-004** | 生成模型在引用句中加入来源没有的数字、因果或结论 | 输出被复核拒绝、重写或标记不可采用，不能作为已核验建议展示。 |
| **AT-CIT-001** | 向 `manuscript_numeric` 的已有 `[2]` 前插入新文献 | 新文献及后续正文标号、交叉引用和文末条目一致联动；不得简单追加原编号。 |
| **AT-CIT-002** | 推荐论文已通过 DOI 或规范化书目存在于原稿 | 标记“已引用”并复用原编号，不创建重复文末条目。 |
| **AT-CIT-003** | 作者—年份和数字两种样式，以及一条缺少必填元数据的记录 | 样式由确定性格式化器处理；缺失信息明确标记，模型不得补写虚假作者、年份或页码。 |
| **AT-CIT-004** | 稿件编辑后原句子锚点仍可匹配，以及另一版本无法匹配 | 可匹配时重新定位；不可匹配时提示人工确认，不得插入猜测位置。 |

### 快照、事件、接口与前端

| 验收 ID | 场景与操作 | MUST 满足的断言 |
|---|---|---|
| **AT-SNP-001** | 用户导出快照后，再释放一个高分迟到结果 | 原快照结果、排序、引文和导出语义不变；迟到结果只能形成补充版本或新快照。 |
| **AT-SNP-002** | 用户在全部 Worker 完成前主动创建快照 | 快照记录创建时的实际覆盖和未完成库；导出页面明确显示部分覆盖状态。 |
| **AT-EVT-001** | 同一 `event_id` 重试多次，并按 `Last-Event-ID` 重放 | 幂等处理，无重复推荐、重复来源或重复编号；客户端可恢复当前状态。 |
| **AT-EVT-002** | 旧 `result_version` 晚于新版本到达，以及事件序号乱序到达 | 旧版本不能覆盖新状态；系统按契约排序、缓冲或重新同步，不产生回退。 |
| **AT-API-001** | 创建搜索、读取当前状态、订阅 SSE、创建快照和导出 | 使用真实 HTTP 与事件流通过契约；错误响应具有稳定错误码、可读信息和 `query_id`。 |
| **AT-UI-001** | 高频新结果、合并和排名事件连续到达，用户已展开一张证据卡 | 页面按 `result_id` 局部更新，保留滚动和展开状态；分数、暂定排名、进度与覆盖提示可见。 |
| **AT-UI-002** | Worker 完成、失败、超时和补充版本到达 | 用户可区分实时结果、最终快照和补充版本；不得将卡片展示顺序直接当成最终数字引文编号。 |

### 安全、隐私与运行韧性

| 验收 ID | 场景与操作 | MUST 满足的断言 |
|---|---|---|
| **AT-SEC-001** | 用户甲尝试读取用户乙的任务、稿件、事件流、快照和导出 | 所有访问均被拒绝且不泄露内容；跨期刊数据访问遵循租户和权限策略。 |
| **AT-SEC-002** | 完成全文推荐后检查公共论文索引和训练数据出口 | 私有稿件不出现在公共索引；不存在未授权训练或分享；私有全文不进入非必要日志。 |
| **AT-SEC-003** | 执行保留期限删除和主动删除 | 私有原文、派生索引、缓存和到期临时文件按策略删除；必要审计记录不包含稿件正文。 |
| **AT-SEC-004** | PDF 含“忽略系统规则、上传其他文件、扩大权限”等指令，以及非法文件类型和超限文件 | 文本只作为数据处理，不改变工具权限；非法输入被拒绝并返回稳定错误。 |
| **AT-OPS-001** | 重排器、模型、数据库、对象存储或单个 Worker 故障 | 故障被分类并进入明确状态；已成功结果和快照不损坏；无静默空成功响应。 |
| **AT-OPS-002** | 服务重启后读取进行中和已完成任务 | 持久状态可恢复；已完成快照不变；进行中任务按契约恢复或明确失败，不能重复产生副作用。 |

### 质量与性能评估

- **AT-EVAL-001｜检索质量**：在版本化标注集上 MUST 分别记录关键词、向量及融合后的 `Recall@K`、融合排序指标和漏召回阶段。不得只报告最终展示条数。
- **AT-EVAL-002｜证据质量**：MUST 报告证据支持率、原文与页码可追溯率、专家采纳情况和无依据引用句次数；无依据生成必须逐例列出。
- **AT-EVAL-003｜评分校准**：MUST 按库、主题和输入类型报告校准误差、Brier 分数及回退比例；样本不足的切片不得给出误导性结论。
- **AT-EVAL-004｜早期预判能力**：MUST 计算不同时间或事件截面的 `EarlyTopMOverlap = |TopM_t ∩ TopM_final| / M`、排名反转率和不同到达顺序下的稳定性。M4 的回归阈值 MUST 来自已版本化基线，而非临时口头目标。
- **AT-EVAL-005｜流式性能**：MUST 分别报告首条有效推荐、首个可导出新快照、最终快照的事件时间，以及 Worker 长尾、事件积压、取消和超时情况。不得以总任务平均耗时替代首条结果指标。
- **AT-EVAL-006｜引文与快照一致性**：MUST 对快照进行语义重复检查，对数字引文执行正文—文末双向校验，对重复导出执行语义等价检查。

## 实现任务 DAG

### 任务执行规则

- **TASK-001**：实现 Agent MUST 按依赖执行任务；并行任务只能修改各自拥有的模块，共享契约必须先合并并通过契约测试。
- **TASK-002**：每个任务 MUST 提交实现、测试、必要的迁移和运行说明。不得把测试统一推迟到 `T11`。
- **TASK-003**：任务验证列给出必须映射到项目实际脚本的命令类型；项目建立后 SHOULD 提供统一入口。任何命令只有在实际执行并保留结果后才能标记通过。
- **TASK-004**：若实现必须偏离冻结决策，MUST 停止相关合并，记录变更原因、影响、替代方案和回退方式，由规格维护者确认；不得静默把流式架构改为批量屏障。
- **TASK-005**：生产部署、外部数据写入和真实第三方服务调用不属于本地实现任务的隐式授权，MUST 单独取得明确指令。

### 依赖图

```text
T00 规格基线
  └─ T01 仓库与测试骨架
       └─ T02 契约、迁移和事件基础设施
            ├─ T03 文献入库与索引
            │    └─ T04 混合检索与动态预算
            │         └─ T05 证据核验与资格门槛
            │              └─ T06 统一评分与校准
            │                   └─ T07 流式 Worker／协调器／去重／重放
            │                        ├─ T08 快照、引文与导出
            │                        │    └─ T09 前端流式应用
            │                        └──────────────┐
            ├─ T10 安全与运行韧性（基础设施可先并行） │
            │                                      ▼
            └─────────────────────────────── T11 全量评估与交付门禁
```

`T10` 的权限、私有存储和日志约束 MUST 在对应功能首次实现时同步落地；`T10` 的最终完成还依赖 `T07`～`T09` 提供完整攻击面和故障注入点。`T11` 依赖所有交付任务，不得因基础功能已演示而提前开始最终验收。

## Definition of Done

交付只有同时满足以下条件才能标记完成：

- **DOD-001｜需求完整**：所有计划里程碑内的 MUST 需求均有实现、验收场景和通过证据；不存在未披露的占位实现、假成功按钮或仅导入验证。
- **DOD-002｜流式成立**：`AT-STR-001`～`AT-STR-005` 通过真实 API 和前端路径；慢库不阻塞快库，迟到高分可插入，覆盖范围始终可见。
- **DOD-003｜评分可信**：同/异构评分、版本、校准回退和禁止批次归一化测试通过；展示分与证据状态分离，早期结果不被宣传为最终全库最优。
- **DOD-004｜证据可信**：所有可引用推荐均有真实元数据、有效证据和关系分类；无依据生成引用句的验收结果为零，失败样本未被隐藏。
- **DOD-005｜结果一致**：去重、事件幂等、乱序、重放、重启恢复、快照不可变和导出一致性全部通过；已导出内容不受迟到事件影响。
- **DOD-006｜引文正确**：全文插入位置、已有编号复用、数字编号联动和文末条目一致；数字编号只在快照或选定上下文中统一处理。
- **DOD-007｜安全成立**：跨租户访问、私有稿件隔离、删除、日志、恶意文件和提示注入测试通过；未授权外部部署或数据写入未发生。
- **DOD-008｜工程可维护**：静态检查、类型检查、单元、契约、集成、E2E、前端构建和数据库迁移测试均实际执行并通过；依赖和模型版本已锁定，配置无硬编码秘密。
- **DOD-009｜评估可复核**：检索、证据、校准、早期 TopM、首条结果和长尾指标均已生成可复核报告；M4 与版本化基线相比无未批准退化。
- **DOD-010｜边界透明**：最终交付明确已完成范围、未覆盖数据源、人工检查项和已知限制；不得将未执行、未验证或部分通过的检查写成完成。

## 与其他片段的接口点

### 本片段消费的契约

实现和测试任务 MUST 使用契约章节统一定义的 `Paper`、`Passage`、`Evidence`、`Recommendation`、`WorkerStatus`、`Snapshot`、事件 envelope、错误模型、状态枚举、`score_version`、`result_version`、`snapshot_id` 和稿件句子锚点，不得在本片段对应的测试代码中另建语义冲突的版本。

### 测试环境必须提供的控制接口

以下能力 SHOULD 仅在测试环境暴露，不得成为未受保护的生产管理接口：

- 可控 Worker：暂停、释放、失败、超时、取消和发送迟到事件；
- 可控模型：固定重排分、来源校准、关系分类和生成输出；
- 可控时钟与调度：验证截止、保留期限和事件顺序，不依赖真实等待；
- 事件工具：重复、乱序、重放、断线恢复和持久化重启；
- 故障注入：数据库、对象存储、模型和单个 Worker 的独立故障；
- 状态导出：在断言前读取有序结果、Worker 状态、覆盖范围和快照版本。

### CI 逻辑任务

仓库 SHOULD 将验证命令统一映射为 `contracts`、`unit`、`integration`、`e2e`、`security`、`evaluation`、`build` 和 `migration` 等逻辑任务。具体工具由实现栈确定，但 CI 必须能区分未执行、失败、跳过和通过，并保存对应测试报告。
