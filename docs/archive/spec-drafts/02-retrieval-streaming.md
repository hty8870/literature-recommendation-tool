## 文献入库与索引构建

本章中的字段名仅用于说明模块交互，字段类型、枚举和完整 JSON Schema 以数据契约章节为准。评分公式、跨库排名和前端展示不属于本章范围。

### 元数据、原文与版本治理

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| ING-001 | 系统 MUST 以 `library_id + normalized_doi` 作为有 DOI 论文的幂等入库键；无 DOI 论文 MUST 使用规范标题、第一作者、年份和内容哈希形成复合键。DOI 规范化 MUST 去除 `https://doi.org/`、`doi:` 前缀及首尾标点，并转为小写。 | 同一文件重复入库不得产生新论文记录；不同版本不得覆盖彼此的历史索引。 |
| ING-002 | 书目元数据 SHOULD 按出版方记录、权威 DOI 注册元数据、PDF 提取结果的顺序交叉核验。系统 MUST NOT 使用 LLM 补写缺失 DOI、作者、年份或页码。 | 关键字段冲突时标记 `metadata_conflict` 并进入隔离状态，不参与推荐；验证日志能定位冲突来源。 |
| ING-003 | 系统 MUST 区分研究论文、综述、更正、撤稿及其他文献类型，并保存 `corrects`、`retracted_by` 等版本关系。更正和撤稿通知默认不得作为普通研究论文推荐；被撤稿论文不得进入可引用集合。 | 类型不明的论文标记 `document_type_unknown`，按当前安全策略隔离或仅进入人工检查；更正声明能关联原始论文。 |
| ING-004 | PDF 解析 MUST 同时保存清洗文本和原始提取文本，并保留二者映射。证据锚点 MUST 至少包含 PDF 页序号、passage 标识和字符区间；版面可用时 MUST 包含印刷页码、章节、段落及页面坐标。 | 任一用于展示的证据均能回溯源文件；无法建立有效映射的片段标记 `trace_invalid`，不得进入可引用推荐。 |
| ING-005 | 双栏、跨栏和断词文本 SHOULD 经版面感知的阅读顺序与去连字符处理。扫描件 MAY 使用 OCR，但 OCR 结果 MUST 带质量状态，不得把低置信文本伪装为精确原文。 | 使用双栏样本验证段落顺序，使用行尾断词样本验证清洗后原文定位；OCR 定位不可靠时返回质量错误而非猜测页码。 |
| ING-006 | 参考文献列表、版权文字和重复页眉页脚 MUST 与正文分字段保存，且不得进入主要正文语义索引。参考文献 MAY 单独用于引用网络或评估。 | 构造“标题只出现在另一篇论文参考文献中”的样本，正文检索不得因此将该论文作为内容证据。 |
| ING-007 | 增量更新 MUST 采用 upsert、失效标记和索引版本机制。单次查询 MUST 绑定一个不可变 `index_snapshot`，不得在查询中途混用两个索引版本。 | 更新期间执行查询，结果只能全部来自更新前或更新后的一个快照；失败重建不得破坏仍在服务的旧快照。 |
| ING-008 | 新索引 SHOULD 在后台构建并原子切换。入库任务 MUST 记录源文件哈希、解析器版本、向量模型版本、索引版本及处理时间。 | 任一检索结果均能定位其索引和解析版本；重复内容哈希不得触发无意义的重复向量化。 |

### 两级索引与离线计算

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| IDX-001 | 系统 MUST 建立论文级索引，至少覆盖标题、摘要、关键词和整篇语义表示，用于宏观召回。 | 只有全文某段相关、标题摘要完全不相关的样本可由段落级索引补充，论文级索引不得成为唯一入口。 |
| IDX-002 | 系统 MUST 建立段落级索引，每个语义块 MUST 关联 `paper_id`、章节和证据锚点。分块 SHOULD 遵循章节、段落和语义边界，而非只按固定字符数截断。 | 任一候选段落可聚合回唯一论文；跨页块仍能保持逐页证据位置。 |
| IDX-003 | 表格、图注和补充材料 SHOULD 使用独立字段和类型标记。其内容只有具备独立有效证据锚点时才可进入证据检索。 | 表格数字或图注命中时，不得误归为正文结论；证据卡片能显示实际内容类型。 |
| IDX-004 | 向量化和关键词索引 MUST 在离线入库或增量更新阶段批量完成。在线查询 MUST NOT 逐篇读取 PDF、重新计算全库向量或让 LLM 扫描全库。 | 在线性能测试的检索路径不包含全库文件读取；索引缺失应返回明确错误而非回退到全库 LLM 阅读。 |
| IDX-005 | 自控库 MUST 使用统一字段定义、清洗规则、分块策略、向量模型和版本。外部库 MAY 使用适配器，但 MUST 输出同一逻辑 Paper、Passage 和 Evidence 引用。 | 同一自控内容在不同库分片中的语义表示可复现；外部能力缺失通过适配状态显式报告。 |

## 候选检索

### 查询构造与输入输出

Worker 的检索输入至少逻辑包含：`query_id`、`library_id`、`input_mode`、原始关键词或论述、可选 `claim_id`、过滤条件、候选预算、`index_snapshot`、模型版本和截止时间。全文模式 SHOULD 先聚类和去重相似论述，再批量生成查询向量。

候选输出至少逻辑包含：论文与段落引用、库内排名、`retrieval_score`、各路召回来源、统一重排器输出、索引与模型版本、已引用标记和证据获取状态。此输出 MUST NOT 被直接视为最终“应引用”结论。

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| RET-001 | 系统 MUST 保留用户原始专业术语和精确查询，查询扩展 MUST 作为额外召回路，不得替换原始查询。 | 对含罕见基因名的查询，扩展查询导致零结果时仍须执行原始精确查询。 |
| RET-002 | 每次有效检索 MUST 并行或独立执行关键词召回和向量召回，结果取并集。系统 MUST NOT 假设关键词命中集合是向量 TopK 的子集，也不得取两路交集作为唯一候选集。 | 测试集必须同时包含“仅精确词命中”和“仅同义改写命中”的论文，两类均能进入候选。 |
| RET-003 | 关键词与向量每路 TopK MUST 分别由 `retrieval.keyword_top_k` 和 `retrieval.vector_top_k` 控制。向量索引 MAY 使用 HNSW 等近似最近邻算法，但必须记录近似召回参数。 | 达到 TopK 后不得宣称库内不存在相关论文；向量未命中不得作为“不应引用”的证据。 |
| RET-004 | 对 DOI、必须出现的基因名或物种等硬约束，系统 MAY 使用精确过滤或加权；只有用户或查询分析明确标记为必需的术语才能使用 `must`，不得把全部扩展词默认设为硬约束。 | 硬过滤条件必须随结果返回，能够解释候选为何被排除；扩展同义词不得错误排除原始术语论文。 |
| RET-005 | 系统 MUST 排除查询者自身论文、无权限论文及当前策略禁止推荐的类型。稿件已引用论文 SHOULD 标记 `already_cited=true`，不得作为新引用重复推荐，但可保留用于核查。 | 自身 DOI 不出现在候选；已引用论文不会被计为新增参考文献；权限过滤在索引查询层执行。 |
| RET-006 | 多路召回 SHOULD 使用 RRF 等排名融合。RRF 只用于库内候选排序，MUST NOT 被直接解释为跨库统一展示分。 | 融合结果不依赖 BM25 与向量分的直接相加；同一库同一查询在固定版本下结果可复现。 |

RRF 可采用以下确定规则，其中 `rank_j(d)` 是文档在第 j 路结果中的名次，未出现的路不贡献分数：

```text
rrf_score(d) = Σ_j 1 / (rrf_k + rank_j(d))
```

`rrf_k` 是配置项，不属于跨库评分参数。段落级结果 MUST 先聚合回论文并保留最优段落、命中段落数和论述覆盖特征，再进入有限候选集；不得因同一论文多个相邻段落占据全部名额而降低结果多样性。

### 重排与证据获取

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| RET-007 | 统一重排器 MUST 只处理初筛后的有限候选，输入 SHOULD 包含原始论述、标题、摘要和候选段落。系统 MUST NOT 对全库逐篇运行重排器。 | 调用日志可证明重排输入数量不超过检索预算；统一重排器输出交给评分模块，不与异构原始分直接比较。 |
| RET-008 | Worker MUST 为拟进入后续核验的候选读取原文及必要上下文，不得只返回摘要比对结果或页码猜测。证据不可用时应输出明确失败原因。 | 原因码至少覆盖 `source_unavailable`、`trace_invalid`、`parse_quality_insufficient`；这些候选不得进入可引用推荐。 |
| RET-009 | 论文真实性、语义相关性和引用关系 MUST 分开判断。候选检索只负责发现可能相关的内容，后续 `verify_relationship` 通过后才可发出合格推荐事件。 | 高相似但关系为 `insufficient` 的候选只能进入诊断或相关候选集合，不得触发 `recommendation_created`。 |
| RET-010 | 检索质量 MUST 分阶段评估，至少记录关键词召回、向量召回、融合、统一重排和证据核验的数量与正确论文召回情况。 | 评估报告能定位正确论文首次丢失的阶段，并计算 Recall@K；不得只报告最终 LLM 输出质量。 |

## 动态 TopN 与候选预算

### 分配规则

`N_i` 表示第 i 个库最多可进入统一重排和证据核验的候选数，不是关键词或向量单路 TopK，也不是最终展示数量。全局预算 B 是所有活跃库可进入上述高成本处理阶段的候选上限。

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| BUD-001 | 系统 MUST 使用带上下限的动态 TopN，MUST NOT 直接按每库论文总数的固定 k% 分配候选。库规模只能用于成本估算和上限控制，不得作为正向相关性权重。 | 同等主题条件下，大库不会仅因论文数量更多而占满全局预算。 |
| BUD-002 | 库权重 SHOULD 综合主题相关性、分主题历史证据通过率、当前头部结果质量、数据完整度与时效性、响应延迟和成本。每次分配 MUST 保存权重特征与版本。 | 任一库的预算都能解释来源；历史库整体质量不得替代当前单篇证据核验。 |
| BUD-003 | 无历史数据的新库或新主题 MUST 使用中性先验并获得探索配额，不得赋予零权重。系统 MUST 保留由 `budget.exploration_share` 控制的少量探索预算。 | 新库在索引可用且主题可能相关时始终有非零候选机会；探索配额不得被历史高权重库挤占。 |
| BUD-004 | 预算 MUST 设置 `budget.per_library_min`、`budget.per_library_max` 和 `budget.global_max`，并在流式过程中根据证据转化情况增量调整。已经发出的有效事件不得因后续预算缩减而撤回。 | 预算缩减仅停止未开始的处理；预算增加不会重复处理已完成的候选。 |
| BUD-005 | 库内质量门槛只能使用该库可比较的检索或重排信号。任何库都不得因响应更快而获得额外隐藏排名加权。 | 响应时间只能影响预算、截止和取消决策，不得直接提高论文的最终相关性分。 |

基础分配采用以下规则，权重须非负并在所有活跃库上归一化：

```text
N_i = clamp(per_library_min, per_library_max, round(global_max × w_i))
```

钳制后若总分配超过 `global_max`，协调器 MUST 按权重从低到高缩减高于最低配额的部分；若所有库均达到最低配额仍超预算，则继续降低可调整的最低配额，最终总分配 MUST NOT 超过全局硬上限。若分配不足， SHOULD 按权重向未达到上限的库分配余量。该过程必须确定性执行并记录结果。

## 流式 Worker 生命周期

### 并行与逐条发布

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| STR-001 | 协调器 MUST 并行启动符合条件的独立库 Worker，并逐条接收结果。实现 MUST NOT 使用等待全部 Worker 的 join、`Promise.all` 或等价屏障后才发布结果。 | 用测试闩锁阻塞库 B，库 A 的证据合格结果仍须在 B 释放前到达协调器和事件流。 |
| STR-002 | Worker 内部 SHOULD 逐条或小批处理候选。每个候选完成证据核验后 MUST 立即发布，不得先积累本库全部结果。小批聚合 MUST 受条数和最长持有时间双重限制。 | 首条合格结果的发布不得依赖本库最后一个候选完成；批处理不得造成无界等待。 |
| STR-003 | 原始候选、进度计数和最终合格推荐 MUST 使用不同事件语义。只有 `support`、`complement` 或 `contrast` 且证据定位有效的结果才能发出合格推荐事件。 | 用户端不会因原始候选到达而误认为其已经可引用；零合格推荐的库可正常完成。 |
| STR-004 | 单个 Worker 的解析、索引、模型或网络失败 MUST 隔离在该库。其他 Worker MUST 继续执行并发布结果。 | 注入库 A 异常后，库 B 结果不受影响；库 A 以失败状态结束，不得伪装成“检索完成但零结果”。 |
| STR-005 | Worker MUST 为每次执行记录 `worker_id`、`attempt_id`、库、索引快照、模型版本、开始/结束时间和处理计数。重试 MUST 使用幂等事件标识和稳定论文去重键。 | 同一 Worker 重试或网络重复投递不会产生重复推荐；日志能区分重试与独立查询。 |
| STR-006 | 协调器到 Worker 的队列 MUST 有界并提供背压。合格推荐事件 SHOULD 持久化后确认，不得在事件未安全交接时静默丢弃。 | 队列满时仅阻塞对应生产者或暂停新候选，不得造成全局死锁；无法交接时必须上报失败状态。 |

Worker 的合格结果至少逻辑包含：`query_id`、`library_id`、`worker_id`、`attempt_id`、论文与证据引用、`claim_id`、关系类型、核验状态、库内检索分、统一重排器输出、索引/模型版本和稳定去重键。`display_score`、全局 `result_id` 和最终排名由协调器后续生成，Worker MUST NOT 自行伪造。

### 截止、取消和迟到结果

| 需求 ID | 规范要求 | 失败行为与验证条件 |
|---|---|---|
| STR-007 | 每个 Worker MUST 支持软截止和硬截止。软截止后 MUST 停止启动新的高成本候选处理，完成或安全终止在途工作并刷新事件；硬截止 MUST 触发协作取消。 | 截止后 Worker 不得无限继续召回；状态明确为 `timed_out` 并携带部分覆盖信息。 |
| STR-008 | 取消 MUST 幂等。Worker 确认取消后不得再启动新处理；确认前已经持久化的事件可保留，但必须带原执行标识。 | 重复取消返回同一终态，不重复报错，不删除其他 Worker 已发布结果。 |
| STR-009 | 协调器 MAY 在证据充分且结果多样性满足策略时提前停止低预期收益 Worker，但当前证据不足时 MUST NOT 只因已有快库结果而强制提前结束。 | 停止决定记录原因和覆盖范围；罕见主题或证据不足时允许扩大检索或继续等待慢库。 |
| STR-010 | 最终化前到达的迟到合格事件 MUST 正常进入增量去重与插入流程。最终快照形成后到达的事件 MUST NOT 修改原快照；满足会话策略时可形成补充版本。 | 已导出快照永远保持不变；迟到结果有明确“补充”状态，不被静默丢弃或改写历史。 |
| STR-011 | Worker 完成、失败、超时和取消 MUST 使用不同状态。最终快照 MUST 记录每个库的终态及实际覆盖范围。 | 部分覆盖不得展示为全库完整结果；用户和下游程序均可读取未完成数据源。 |
| STR-012 | 查询重试 SHOULD 固定原 `index_snapshot` 和模型版本。无法复现时 MUST 创建新执行版本，不得把不同版本结果无说明地合并。 | 重试结果可复现；索引或模型变化有明确版本边界。 |

### 本章必须通过的集成验证

- **ING 验证**：重复导入保持幂等；更正声明关联原论文；双栏、断词和跨页证据能回溯原 PDF。
- **RET 验证**：罕见精确术语样本与改写语义样本均能召回；自身论文被排除；已引用论文被标记；高相似但证据不足者不能成为合格推荐。
- **BUD 验证**：大小悬殊的库不会因固定比例产生失衡预算；新库获得探索机会；总分配从不超过全局硬上限。
- **STR 验证**：慢库被测试闩锁阻塞时快库仍可发布；单库异常不影响其他库；软/硬截止均能退出；重试和重复事件不产生重复推荐；快照后迟到事件只进入补充版本。

### 与其他模块的配置接口

实现时 MUST 在统一配置中提供以下键，具体默认值由配置章节集中定义：`retrieval.keyword_top_k`、`retrieval.vector_top_k`、`retrieval.rrf_k`、`retrieval.max_passages_per_paper`、`budget.global_max`、`budget.per_library_min`、`budget.per_library_max`、`budget.exploration_share`、`worker.max_concurrency`、`worker.micro_batch_size`、`worker.micro_batch_max_wait_ms`、`worker.soft_deadline_ms`、`worker.hard_deadline_ms`、`worker.queue_capacity`、`worker.accept_late_events`。
