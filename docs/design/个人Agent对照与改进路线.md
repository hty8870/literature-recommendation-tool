# 文献推荐工具：相对个人 Agent 的价值与改进路线

日期：2026-11-14。性质：产品分析与后续提案，不是已实现能力或效果报告。用户已批准对抗性评审修复；本文新增产品功能须在实施前按阶段纳入主 SPEC，不能自动扩大当前范围。

## 1. 结论：不再造一个会搜论文的聊天助手

Codex 等个人 Agent 在具备联网、全文访问、脚本、文献工具和足够上下文时，可以完成检索、阅读、比较、生成引用建议，甚至调用本产品同一套工具。不能把“它不会找 DOI”“它只能看摘要”“它没有多 Agent”当作竞争前提。

本项目值得做的不是把这些动作包一层聊天界面，而是把高频、严格的科研引用工作变成**可核查、可复用、可持续维护的文献证据服务**：

> 不只告诉用户“这篇相关”，而是说明“它与稿件哪条论述有关、原文在哪里、支持到什么范围、为什么不能支持更强的表述，以及如何安全纳入现有引文体系”。

这仍是待验证价值主张。若用户只偶尔做开放式方向探索，个人 Agent 可能更灵活、更便宜，专用产品未必有优势。若不需要私有库、重复使用、证据审计、多人协作或文稿引用维护，优先给现有 Agent 提供一个工具/Skill，而不是建完整平台。

## 2. 优势属于什么，而不属于什么

| 用户任务或痛点 | 个人 Agent 可能的表现与边界 | 本产品可提供的机制 | 优势成立条件与代价 |
|---|---|---|---|
| 开放式了解新方向 | 擅长交互澄清、多轮跨领域探索、临时组合工具 | 提供主题候选与证据检索工具，不强迫固定流程 | 不预设优于 Agent；先作为其检索后端 |
| 大库重复检索 | 无持久索引时重复搜索/读取；有索引工具时可消除此差距 | 预处理、版本化索引、权限过滤、增量更新 | 需足够重复请求摊销入库成本；不是向量库本身构成壁垒 |
| 相关但不能引用 | 一次性回答可能缺少逐 claim 的适用条件和反证 | ClaimLink、关系核验、原文证据、物种/条件/因果范围 | 依赖可靠解析、标注和模型；不能保证自动判断永不出错 |
| 核对出处费时 | Agent 可以给链接，但链接未必直接到具体支撑位置 | 稳定证据包、页码/坐标与一键对照，保留版本 | 来源可合法访问；位置与阅读顺序实际核验有效 |
| 结果不全却像全覆盖 | Web 搜索通常无法证明覆盖所有库 | 明确所选库、索引日期、未覆盖/超时、截断和部分结果 | 只能说明已知检索范围，不能证明整个学科无遗漏 |
| 反复找同一篇、不同轮次答复变动 | 可借记忆/项目文件缓解，但不必有结构化状态保证 | Work 去重、claim 独立绑定、快照、重放和版本差异 | 需要维护事务与生命周期，不是多写提示词就得到 |
| 参考文献维护 | Agent 可用脚本或文献管理器，复杂 Word 修改仍易出错 | 引文 registry、编号策略、CSL、受支持结构的安全写回 | 不重造 Zotero；复杂文档明确支持范围并回退为变更提案 |
| 敏感未发表稿件 | 取决于具体 Agent 部署、模型提供方与组织策略 | 租户隔离、许可过滤、数据最小化、可执行删除策略 | 云端不天然更私密；本地 Agent 可能更有优势 |
| 长期变化 | 临时会话未必持续追踪新论文、更正、撤稿 | 订阅式增量检查和现有引用风险清单 | 要有持续使用需求和可负担的数据源维护，后续阶段再做 |
| 成本和时延可控 | 可临时设置预算，但一般任务路径变化大 | 阶段预算、有限候选、跨请求可安全复用的公共数据缓存 | 要计入索引、存储、运维、人工审核的全成本 |

**不构成独立优势的内容**：LangChain、Tower、多 Agent、Skill、RAG、向量搜索、云端部署、流式动画。它们都是手段，且个人 Agent 也可使用。统一分数也只有通过同尺度验证和用户理解测试才有价值；一个漂亮的 93 分可能比明确“范围不匹配”更误导。

## 3. 分开两种任务，避免一把尺子

### 3.1 引用论述（citation mode，首要闭环）

输入稿件中的具体论述，输出支持、补充、对照/反证、证据不足，并带适用范围与定位。保留跨论文冲突，不把相反结论压成一个“更相关”分数。

卡片的优先信息：目标论述 → 关系与限制 → 原文对照 → 来源/状态 → 分数组与覆盖 → 可编辑引用建议。分数服务于筛选，不替代证据。

用户修改论述或引用句后，旧核验绑定的内容哈希失效；重新核验或明确标“已编辑，未重新核验”。这能防止系统核验了 A、用户复制了更强的 B，却沿用绿色标记。

### 3.2 方向探索（discovery mode）

输入宽泛主题，输出主题相关候选、研究分支和可能的阅读路径；不凭一个关键词推断用户需要支持什么论断，也不把主题分解释为“应该引用”。

先用现有检索结果的轻量分组和主题说明；引文网络扩展、综述图谱只在检索盲区实验表明有收益后添加。方向探索不强行走全文写回与引文编号流程。

## 4. 待验证的产品形式：作为个人 Agent 的证据服务

先稳定独立于聊天框架的领域 API；前端用于原文并排核查和人工确认。后续用薄工具适配层让 Codex 等调用相同能力：

1. `search_candidates`：返回检索范围、候选身份、分数尺度和任务状态，不承诺可引用。
2. `get_source_evidence`：返回授权范围内证据与稳定定位，不默认传整篇论文。
3. `verify_relationship`：输入具体 claim 与证据引用，输出关系、适用范围、拒绝原因及版本。
4. `format_citation`：从已核验元数据格式化，不让模型补写 DOI/作者/卷期。
5. `get_snapshot`：返回固定截点与覆盖；导出是另行用户授权的操作，不因读取论文而自动执行。

这是接口方向，不是在本阶段承诺 MCP 或新增五套服务。P0 先验证独立证据闭环；D 路线等现有 API 可用后用最薄脚本客户端验证，再决定是否需要 MCP，避免维护两套语义。个人 Agent 可以负责澄清、探索、写作，但外部编辑文本默认未核验，只有送回产品按 claim/证据/文本内容版本重新校验后才可获得“已核验”标记；导出不得信任外部 Agent 自报状态。私稿及其 claim 向外部 Agent 传输须取得用户明确授权并记录处理方、内容范围与保留政策；否则仅使用公开或非敏感数据。

## 5. 下一步路线：按收益与风险排序

### P0：用最小真实任务证明价值，而不是先做平台

- 选 20–30 个代表性任务做初始可行性实验：具体 claim、宽泛方向、同名/术语歧义、否定结果、超范围支持、同论文多 claim、没有可引用结果。
- 50 篇样本用于建立解析和证据闭环，不用于证明百万论文库性能。性能用获许可的更大语料或明确标注的合成索引，不能把合成负载当科学召回评估。
- 先从少量 claim 输入，做“检索 → 证据定位 → 范围判定 → 人工核查 → 格式化引用”完整闭环；保留多库慢通道与重连测试。
- 采用修订 SPEC 的模块化单体和有限并发。不要为对照实验预先购买新云资源或搭建多 Agent 平台。
- 预先记录可接受的人工核查时间、错误风险和预算；若证据定位仍不可信，先修解析，不提高模型自由度。

**交付证据**：真实任务卡片、人工修正记录、失败分类、时间/成本统计和对照结果。此阶段的少量样本只能淘汰明显无效路线，不足以声明普遍优越。

### P1：集中补齐引用工作流的痛点

- **证据对照卡**：目标 claim 与 PDF 局部并排展示；高亮证据句，分别显示文本偏移、PDF 定位、阅读顺序检查状态，以及上下文、物种/条件限制和二手来源标记。高亮不等于关系核验通过。
- **引用缺口与冲突清单**：逐条显示已覆盖、证据不足、有冲突、需缩小表述范围，不强行凑推荐数。
- **编辑后失效机制**：对 claim、证据包和引用句绑定内容版本；编辑后重新验证或撤销“已核验”状态。
- **引用交接包**：先输出 CSL JSON/BibTeX 或已有规格的安全格式与变更建议；与成熟文献管理器衔接。复杂 DOCX 原位修改作为单独验收项目，不能因快捷导出而放弃原需求。
- **公平覆盖**：合作期刊库优先只能来自用户明确范围；跨库扩展时展示范围限制，不能把业务导流权重伪装成学术相关性。

**准入条件**：先证明这些操作减少人工检查或关键错误。每项新增功能先补需求 ID、验收与版本规则，再实现，不一次性扩大第一版。

### P2：把持续积累变成优势

- 小语料先用定时重建/状态刷新；当规模、更新频率或重建耗时实测超预算，再增量更新。可先仅对用户保存的引用集检查更正/撤稿风险，不建全学科监控平台。
- 对重复公共语料安全复用解析与向量；私稿派生缓存严格租户内隔离，并受删除生命周期约束。
- 提供薄 Agent 工具适配，比较“Agent + 本证据服务”和“Agent + 普通搜索”的差异。
- 收集用户“采纳/不采纳及原因”，区分主题不符、范围不符、定位错误、重复引用等；反馈不能未经授权用于训练，也不能直接当无偏金标。

### P3：有测量证据再增加复杂度

- 词法召回不足，再评估 BM25 专用引擎；大规模过滤 ANN 漏召回，再评估索引参数和架构。
- 简单轮转不能满足公平性/延迟目标，再评估更复杂调度；跨节点容量/故障隔离有实测必要时才拆服务。
- 确定性查询对复杂任务不足，再启用有界规划器；只有单规划器基线证明不够，才讨论多 Agent。
- 跨库有足够、独立、覆盖目标领域的标注后，再发布校准分数；宁可诚实分组，不要提前造一个全球统一概率。

## 6. 公平实验：究竟比什么更好

### 6.1 四条对照路线（分阶段开展）

| 路线 | 配置 | 回答的问题 |
|---|---|---|
| A 现实个人 Agent | 固定版本个人 Agent + 用户平时可用搜索/全文工具，允许合理 Skill 和脚本 | 现实替代方案够不够好？ |
| B 等条件个人 Agent | 同模型、同语料访问、同检索工具、同时间/token上限，允许 Agent 自行编排 | 专用流程本身是否带来增益？ |
| C 本产品 | 同输入和资源约束、固定版本证据工作流 | 质量/时延/成本/人工复核有什么变化？ |
| D 后续集成 | 个人 Agent + 本产品证据 API | 产品更适合独立应用还是 Agent 基础工具？ |

A 是产品价值的主对照，B 用于机制归因，不能互相替代。P0 先做 A vs C；只有需要解释差异时才做 B，D 等接口可用后再做。每条路线登记资源清单：全文权限、基础检索工具、索引构建与预处理时间/摊销成本、模型族与版本、总预算、Skill/提示词、重试/超时及硬件。B 可用同等基础索引和原始检索接口但不能调用产品关系核验/快照等工作流；调用本产品证据工作流的归 D。产品与 Agent 获得同等数据权限，任何工具或模型差异均显式报告，不能用摘要对全文的落差证明架构优越。为各路线提供同等调优预算，冻结后使用留出任务；预先登记优效/非劣界值，不事后定义胜出。

### 6.2 指标和判定

- **证据与关系**：人工判断可引用准确率、逐字/定位正确率、超范围支持率、二手来源误当原始证据率、错误生成引用句率。
- **有用性**：人工接受的唯一论文数、每条 claim 覆盖、冲突发现率；有限候选池上的召回称 pooled Recall，不声称完整宇宙真召回。
- **用户劳动**：找到原文证据耗时、完成引用耗时、修改次数、任务完成率；盲评与顺序随机化，控制学习效应。
- **速度与稳定性**：首条可核查结果时间、全部指定任务完成时间、p50/p95/p99、失败/超时、流式可交互性。
- **货币成本**：模型、检索、索引/存储摊销、许可/采购、标注评估和维护；同时报单次与月度使用假设。用户劳动单独报时长，不重复货币化计入；若需要总经济成本，明确时薪假设且仅计一次。
- **可信与安全**：覆盖提示可理解性、授权隔离、提示注入越权、删除回执、撤稿状态变化后的导出阻断。

硬约束先通过，不能用速度抵消权限泄漏或明知无证据仍给引用句。citation mode 主指标是通过同一无依据引用率/定位错误率门槛后，完成可核查引用的人工时间和独立报告的货币成本；门槛和置信判定试验前登记。discovery mode 主指标是盲评阅读价值、研究分支覆盖及完成探索任务的人工时间，不套用 claim 覆盖率。两模式分开判定，禁止合并均值掩盖失败。论文数量仅作辅助，避免靠灌入结果取胜。

目标阈值在试验前由实际用户任务基线制定并登记，不在看到结果后临时调低。P0 的 20–30 个任务仅作形成性筛查，按模式报告原始结果、失败案例与中位数，不报告可推广的 p99 或推断性区间。正式实验再按效应量与功效确定样本量，可从 200–300 条人工 claim 金标的标注计划起步，采用独立标注和仲裁，并报告样本量、分层结果及适当的 95% 区间；尾部分位数仅在样本足够时报告。50 篇 PDF 先按版式/文字层/表格/断词分层审计并留出评估集，不能仅靠调试样本证明质量。样本中零错误不是零真实风险；约 3/n 的零事件上界仅适用于独立同分布近似，不用于便利样本或相关 claim 直接推断。

### 6.3 停止或转向规则

- 以现实 A 对照作产品决策：若 C 未超过预登记的最低有意义收益且没有其他已验证价值，不扩大独立聊天产品，考虑工具化或停止无差异功能。B 仅解释差异来源：B 与 C 接近但 A 较弱，价值可能是工具集成；B 弱于 C 但现实 A 已足够好，仍不足以证明市场价值。样本不足则结论为不确定，不以“没显著差异”声称非劣。
- 若优势只来自专有/预处理语料，明确价值在数据接入与维护，不能归功于多 Agent 架构。
- 若检索召回好而核验差，优先修证据定位、范围判断与人工复核；不是再扩大候选量。
- 若用户只要研究方向而不需要逐条引用，提供轻量探索入口，不强迫走重量级核验链。
- 若持续使用不足以摊销成本，优先本地/按需工具形式，云端常驻不是目标。

## 7. 与本次修复的关系

本次立即修复的三层身份、证据有效性、范围判断、可比较分数、状态一致性和导出闸门，都是上述价值成立的基础。它们是设计契约，不是已实现竞争优势。

下一步推荐先做 P0 的真实闭环与对照，再把 P1 中最能减少人工劳动的两项纳入实现计划。不要在已有规格尚未跑通时同时追加知识图谱、多 Agent 团队、复杂调度、全学科订阅和 Word 全结构编辑器。

## 8. 依据与边界

本分析不依赖某一 Codex 版本的功能上限，比较对象按实验时实际可用工具定义。成熟技术来源沿用 `文献推荐工具_对抗性评审.md` 的官方链接（Vespa 分阶段排序、PostgreSQL、CSL/citeproc、Crossref 撤稿信息与 OWASP）；这些来源支持机制选择，不证明本产品优于个人 Agent。

本轮没有运行个人 Agent 与产品的真实对照、用户研究、性能或科学质量测试。因此所有“可提供”“能补齐”均是可检验假设，不是营销结论。
