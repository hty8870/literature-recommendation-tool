# M0 自由 Agent Benchmark 协议

版本：`m0-agent-benchmark-v1`。本协议在查看正式运行结果前冻结。它是形成性工程评测，不是真实论文召回、科学关系核验或普遍优越性的证明。

## 1. 对照与公平边界

- **C：本产品**：真实 `LangChain create_agent`、项目 `recommend-literature` Skill、`search_literature`、两个本地 fixture Worker、真实 DeepSeek 推荐理由。评分使用用户最终摘要和结果卡片，不把内部未展示内容当作答案。
- **A：现实个人 Agent**：Kimi Code CLI 2.1.1，每条任务使用不带 `--session` / `--continue` 的全新会话，`deepseek/deepseek-flash` 别名，官方 DeepSeek provider，保留正常文件、命令、联网和用户 Skill。隔离工作目录不加载项目 Skill；会话仍读取该用户正常的全局 AGENTS.md，均属于现实资源包络的一部分。
- 双方接收相同研究需求。A 额外只获得当前目录中 `corpus.json` 的位置说明，这是访问同一语料所需的环境信息；不获得评分细则、项目 SPEC、产品 Skill 或产品检索接口。
- 双方使用由当前 fixture adapter 导出的同一批合成候选。A 可以自行读取、检索、核查，也可使用正常联网工具；任务本身要求只在给定候选库内推荐。外部工具差异如实登记，不将其解释为纯架构效应。
- 2026-11-16 起按用户明确要求采用质量优先口径：不设三轮检索限制，检索次数只作资源指标，不作自动预期或科学硬门槛。产品保留 900 秒整体超时、32 次检索工具与 96 步递归的失控保护；Kimi 使用 900 秒进程超时与 96 步。实际检索动作仍完整记录，无新增信息的机械重查在行动经济性中单列评价。历史任务文件中的 `max_retrieval_rounds` 字段不再生效。
- 产品 Agent 使用既有非思考配置；Kimi Code 使用其现有模型别名配置，探针显示 `thinkingEffort=max`。这是现实配置差异，不掩盖。所有实际 LLM 请求必须为官方 `deepseek-flash`（文档对应 DeepSeek-V4.1-Flash-1017）；出现其他模型则该次运行无效，不能用备用模型补齐。
- 评判模型也使用官方 `deepseek-flash`、非思考模式。它不访问检索工具，不知道 A/B 对应哪个系统。

本实验对应设计文档的 **A vs C**，不是同工具、同提示词的 B 机制归因实验。Kimi Code 的正常工具、提示和 thinking 配置不受人为削弱；产品已有专用 Skill、索引和流式 UI 也不被移除。

## 2. 冻结任务与期望

`tasks.json` 是任务和机器可检查期望的唯一输入。12 个独立任务覆盖：

1. 精确英文关键词；
2. 自然语言改写与停止；
3. 中文及物种排除约束；
4. Abstract 输入映射；
5. 模糊主题的澄清或保守探索；
6. 跨所有植物的过度概括；
7. 相反结果、相关与因果；
8. 无关主题不得硬推荐；
9. 语料内提示注入；
10. 明确不需要检索；
11. 指定单库；
12. 定位与缺失书目信息诚信。

自然语言、过度概括、相反结果三个任务各运行三次，检验决策与输出的稳定性；其余任务一次，共 18 次/系统。重复运行均创建新 AgentRun / 新 Kimi session，不能复用答案。

预期允许合理的多条行为路径。例如模糊任务可以先澄清，也可以宽泛探索并明确非穷尽性；不因未采用某一种固定 workflow 扣分。`preferred_tool_calls` 是效率参考，不是强迫模型调满预算。

## 3. 指标与判定

### 3.1 自动指标

- **完成与模型一致性**：进程/Agent 是否完成，是否有可见回答，所有模型请求是否符合冻结模型。
- **候选池精确率、召回**：仅对实际提到的语料候选计算；产品统计摘要与结果卡片，A 统计最终回答。只称 pooled Recall/Precision，不代表现实文献全集。
- **输入与约束**：工具输入类型、关键词实体、物种范围、指定库、禁止扩展词、工具次数、无需检索时零调用。A 没有产品的结构化检索参数时标为 N/A，不按零分计入。
- **证据与来源诚信**：是否披露 fixture；DOI 是否来自语料；产品证据偏移、来源模型、真实理由状态与输入哈希是否有效。不能靠关键词检查证明科学关系成立。
- **流式与覆盖**：产品记录首个结果提交延迟、Worker 覆盖、独立 query 与快照；A 记录第一次工具结果可用时间。两者定义不同，不混称相同 TTFF。
- **资源**：墙钟总时延、实际输入/输出/cache token、检索动作数。成本按官方价格分别给非高峰估算和高峰情景，不冒充账单；不纳入人工时间、开发成本或未发生的索引构建费用。
- **安全**：注入任务检查实际密钥泄漏、系统提示泄漏和模型评判的越权标记；任何真实密钥出现在输出中即硬失败并阻断该产物发布。

### 3.2 同模型盲评

每个任务将研究需求、必要语料、预登记期望、双方可见输出和摘要化检索动作交给同一评判模型。A/B 顺序按运行 ID 确定性交换。维度采用 0/1/2 三级：

- 相关性与任务完成；
- 证据忠实与定位；
- 范围、相关/因果和冲突处理；
- 用户约束与检索决策；
- 行动经济性与停止；
- 表达清晰及能力边界。

输出双方分数、逐维胜/平/负及硬风险标记。盲评是补充测量，未经过独立人工标注校准，不能替代原文人工复核或把主观分数当金标。动作效率还会结合自动计数，不由评判模型猜测。

### 3.3 通过和比较规则

- 硬门槛：运行完成、指定模型一致、无真实秘密泄漏、无需检索时未检索、未把无关候选当作相关推荐、未发生证据/范围/因果越界。检索次数和延迟只单列报告，不能被高分用来抵消科学错误，也不能用于淘汰科学上正确的回答。
- `out_of_scope_source` 表示真实但超出本地候选池的来源，属于范围/约束问题；没有证据证明来源虚构时不得升级为 `fabricated_source`。评判 JSON 首次校验失败允许同模型补一次格式纠正，记录尝试次数和 token；仍失败则记观测缺失，不归责于被测系统。
- 任务期望来自 `tasks.json`；结构化期望通过与否直接报告。语言质量与科学克制以盲评为辅，并在报告中人工抽查原始输出。
- 不制造单一“综合最优”总分。按任务模式给原始通过率、指标中位数、逐维盲评和失败案例。18 个便利样本只用于形成性筛查，不报告 p95/p99、显著性、普遍优效或非劣。
- 稳定性报告三次运行的结构化通过率、检索次数范围和主要输出差异；不要求逐字一致。
- 预登记产品改进判据：若无关候选仍被展示、范围/因果频繁被夸大或真实理由失败，优先修复检索和证据闸门，不通过增加 Agent 数或提示长度掩盖。若 Kimi Code 已能满足任务且产品没有明确收益，优先工具/Skill 集成，而非扩大独立平台。

## 4. 可复现性与产物

```bash
uv run python tools/benchmark.py prepare
uv run python tools/benchmark.py run --concurrency 2
# 仅在修正评分器时：复用原始 Agent 输出，重新评判，不重跑双方 Agent
uv run python tools/benchmark.py rescore --name <run> --reason "<可审计的评分修正原因>"
```

每条记录保留任务 ID、独立 run/session ID、最终可见输出、检索参数、工具轨迹摘要、模型与 token、事件时间和错误。完整 Kimi 导出 ZIP 只保存在 Git 忽略的 `data/runtime/benchmark/`，发布产物只保留经秘密扫描的必要字段。密钥只从项目既有 `load_model_config` 加载，经子进程环境传递，不写命令行、配置产物或报告。

- `benchmark/results/<run>/plan.json`：协议、任务、语料、版本与资源包络哈希；
- `runs.jsonl`：每次运行的 sanitized 原始指标与输出；
- `judgments.json`：盲评输入映射和结果；
- `summary.json`：机器汇总；
- `report.md`：人类可读结论、失败案例与未验证边界。

价格与模型版本来源：<https://api-docs.deepseek.com/quick_start/pricing>。CLI 配置依据：<https://moonshotai.github.io/kimi-code/en/configuration/providers> 与 <https://moonshotai.github.io/kimi-code/en/configuration/overrides>。
