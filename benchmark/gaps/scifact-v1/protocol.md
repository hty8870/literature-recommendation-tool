# 研究证据能力空洞基准：SciFact v1

## 目的与预登记

本协议在查看本轮被测输出之前冻结。目标不是保证产品获胜，而是定位“检索相关研究／找应引用论文”的真实质量缺口。产品运行代码与 Skill 在本轮冻结，不根据本轮测试结果调参后仍称首次确认。

外部主数据为 AllenAI **SciFact**：原始开发集 300 条专家编写的科学论断、5,183 篇真实题名／摘要、逐文支持或反驳标签与证据句。使用上游原始 `claims_dev.jsonl`，不使用 Hugging Face 展平后的 450 行代替 300 个任务。命题和金标不是本项目 Agent 生成的。公开数据可能进入模型预训练，因此只是对本项目未调参的公开挑战集，不声称模型从未见过或跨学科普遍优效。

- 数据及任务说明：https://github.com/allenai/scifact
- 论文：https://arxiv.org/abs/2004.14974
- 数据格式：https://github.com/allenai/scifact/blob/master/doc/data.md
- 上游许可证：https://github.com/allenai/scifact/blob/master/LICENSE.md
- 原始下载：https://scifact.s3-us-west-2.amazonaws.com/release/latest/data.tar.gz

上游 LICENSE 指定论断／标注 CC BY 4.0、摘要 ODC-By 1.0；Hugging Face 卡片存在不同许可证摘要，本任务以原始上游声明为出处记录，不把该数据加入生产论文库或公开重分发完整摘要。下载字节、解包成员、规范化语料和选题均保存 SHA256。

## 从已有基准借鉴什么

- [LitSearch](https://github.com/princeton-nlp/LitSearch)：文献检索问题不能只靠题名词面泄题；候选发现应与引用意图区分。本轮不冒充运行了 LitSearch 的 597 题。
- [BRIGHT](https://arxiv.org/abs/2407.12883)：语义相似不等于推理相关；同主题但方向／对象不对的文献是实质性错误。论文报告的检索器差距不等于证明现实通用 Agent 的分数。
- SciFact：把“找到了题名”拆成检索到证据文献、支持／反驳判断、真实证据句三个独立层次。反驳论文同样是有价值的检索结果。

## 两层实验

### A. 全开发集的确定性引擎诊断

对所有有标注证据的开发论断分别运行当前 BM25 与 BM25+E5/RRF。用同一原始论断、同一语料，报告已标注证据的 Recall@5、Recall@20、nDCG@5、零召回和分标签切片；无证据标注题不记零分召回。另报告原生生产候选窗口，而不是悄悄把 Top20 当默认产品 Top5。两次重复应得到相同 ID／分数／顺序。

本轮不训练 LTR，也不把共同基础分或列表 LLM 称为已训练 LTR。既有两版 LambdaRank 退化且未接运行时，必须如实保留该事实。

### B. 冻结子集的端到端产品／Kimi 对照

选择规则只使用官方标注和固定 SHA256 次序，不读取任何被测结果：

1. 先选 4 条至少两篇证据文献的论断；
2. 再选 8 条单篇 SUPPORT、8 条单篇 CONTRADICT；
3. 再选 4 条无标注证据的论断；
4. 上述 24 案按 `cited_doc_ids` 去除共享论文家族，避免把同一篇论文的许多改写算作独立样本；不足时直接失败，不按结果补题。
5. 另从剩余论断确定性选择 2 对共享相同引用论文、标签方向相反的最小对照，共 4 案；同对作一个簇报告，不把 28 次运行冒充 28 个独立研究家族。

双方读取同一 5,183 篇语料，不获得官方 `evidence`、`cited_doc_ids`、标签、证据句索引、分桶或评分规则。原始论断保持英文，不由项目模型改写出题。双方同样要求：找至多 10 篇最相关的支持／反驳候选，提供稳定文献 ID、逐字摘要依据、理由和边界；没有证据可以返回空列表。所有结果仍是摘要级候选，不是全文引用资格。

- 产品：本机真实自由 LangChain Agent、Skill、来源 ReAct 子 Agent、当前混合检索、共同分和 LLM 列表终排，使用既有真实应用调用路径。
- 对照：每案全新 Kimi Code 会话，正常全局工具与 Skill 保留，可以自行扫描、写内存检索代码、补查，不提供产品接口或产品 Skill。临时目录仅含同一 `corpus.json`，不含金标。
- 所有实际模型调用均须官方 `deepseek-flash`；保持既有双方 thinking 配置差异并登记。未验证模型身份或会话隔离者不作为有效完成。
- 双方 900 秒与 96 步技术安全上限，产品另有现有 32 次父工具安全上限。次数、token、速度只作资源信息，绝不因超过三轮或回答慢而判质量失败。
- 两次候选缓存复现和新上下文 Agent 稳定性是不同问题；本轮不宣称新上下文回答逐字不变。

## 对齐最终交付口径

双方最终回答要求同一 JSON 结构，代码仅解析最终回答，不把产品的所有候选卡片冒充它最终选中的论文，也不把排除／背景性提及当正推荐。原始输出保存；格式失败不能悄悄由另一个模型补写答案。工程格式失败与科学证据错误分开报告。

`papers` 包含 `doc_id`、`stance`（SUPPORT / CONTRADICT / INSUFFICIENT）、`quote`（逐字连续摘要片段）、`reason`。`conclusion` 概括论断证据状态。输出只是评测用公共交付格式，不修改产品 API 或固定 Agent 检索流程。

主要质量指标：

- 官方标注证据文献 Recall@5、Recall@10、nDCG@5：双方相同最终 papers 顺序；未知／未标注文献不自动当不相关。
- 正确方向证据覆盖：只有找到目标、方向正确且 quote 逐字属于该文才得分；仅命中题名不能抵消把反驳写成支持。
- 证据句覆盖：逐字片段与官方 rationale 的重叠单列，不以重叠自动证明语义蕴涵；完整 rationale 是充分而非唯一表达方式。
- 已标注论文方向错误、未知 ID、重复身份、虚构原文、未判相关率分别报告。没有证据标注的任务，空答不等于证明现实世界不存在论文；非空未标注答案进入原文复核，不自动算幻觉。
- 从同池原始候选到 LLM 最终榜单／父 Agent 最终选择的逐阶段召回，定位漏检、源提交丢失、重排挤出与最终综合丢失。
- 同模型匿名语义复核作为辅助，不覆盖官方标签；实际指出的越界必须附同侧逐字回答证据。不能因输出更长、来源更多、速度更快给质量胜利。

## 判断与停止规则

不制作含速度／成本的综合总分，不以框架复杂度或 LTR 名称加分。预登记的“观察到实用优势”至少要求：产品正确方向证据覆盖均值高出 0.10，至少 3 个不重叠研究家族的明确质量胜例，且已标注方向错误与虚构原文不更多；否则如实报告未观察到优势。小样本差值不是统计优效结论。

所有 300 题的引擎指标与全部 28 案输出均保留，不能挑选产品胜题作总体结论。报告配对差值、按研究家族重采样的描述性 95% 区间、双方胜／平／负和具体错误。看到结果后可提出下一轮修复，但不在本轮冻结运行中改产品；后续调参需新运行名和新确认数据。

本轮没有覆盖并应明确列为后续的空洞：真实全文页段定位、任意第三方商用库权限、全面系统综述召回、版本／撤稿实时治理与超大库分布式性能。不能把它们因未测试而记为产品胜利。
