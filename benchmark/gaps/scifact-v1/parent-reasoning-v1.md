# SciFact 父 Agent：推理档对照

沿用[已经封存的家族划分、计分与护栏](parent-evidence-v1.md)。两种回执 V1 未取得主指标增益，测试家族未用，不改变历史结果。此试验不再改回执、提示、排名或候选，只测父模型的 API 默认推理档与显式 `high`。三道旧训练题验证了原生 Responses `json_object` 解析，另在旧训练题验证 `high` 与相同结构化返回可共存。两臂一律用同一个 JSON 传输配置，不能把与上批的绝对差值归因于推理档。

对已经分出的 16 个验证家族做配对；分组没有因回执试验输赢而改变。不拟合参数或权重。按同一顺序和证据版本产生候选，只读同批已冻结的验证回放；终测仍独立构建同池输入，且只有验证放行才生成终测题面。真实 API `gpt-6-luna`、`store=false`、新上下文。回放同一题最多并行两次；端到端每一臂串行分配题目，实际检索、源 Agent、重排、最终守门照常，不强制 JSON 模式。只有父模型启用 `high`；来源、重排、引用建议和独立审查的推理档不变。审计请求配置、服务模型、报告的推理用量与失败；服务商没有回显档位时，不宣称从响应元数据核实了它。

采用原协议 +5 个百分点、护栏非退化的验证门槛；留出还须至少 3 个胜家族及通过护栏；全产品才决定能否考虑进入默认。整组格式和完成仍必须报告。新版是产品内同模型优化，不是公众服务发布或胜过 Kimi 的证据。不通过不消耗当前留出；不根据留出挑选推理档。
