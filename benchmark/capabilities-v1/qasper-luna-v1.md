# QASPER v0.3：给定论文的证据问答（Luna 首批诊断）

本单元落实能力基准 D/E，**不是新用户独立留出、书目召回、OCR 或可引用资格测试**。不用于判定产品综合胜负。

- 源：公开 [QASPER v0.3 test](sources.md)，锁定原始压缩包和内部 JSON 指纹。原始问题不改。限定可访问的文本投影：完整题名、摘要、正文段落与发布的图表标题，不输入图片、题目旁的答案、证据索引、作者身份字段或其他题目。统一折叠段内空白，加入中性段号与原章节名；不摘取金标段落拼材料。有些原题需看图表而数据不含图表单元时，只接受至少有一个完整金标证据集合能映射到供应文本的可答题；在固定文本不读图的前提下判。混合可答性题仅诊断，不算确定真值。
- 36 个不同 arXiv 文档：12 个仅含抽取答案、6 个仅含是非答案、6 个仅含开放综合答案（按能映射原文的标注类型；其他未映射类型不会混算）；8 个所有标注均不可答；4 个分歧题。按问答 ID 的固定 SHA-256 次序选题；先分歧、缺口、是非、开放、抽取，以减少小桶被较大桶占用。同一篇最多一题，不纳入此前协议展示的例题，也不因模型表现替换题。先完成两道分层探针（抽取与缺口，各一，属于预锁样本），没通过技术对等性则停止批次并保存原失败，不能顺势修改题目。
- 产品走真实本地 ASGI 上传、解析和原 `AgentRun` / `read_manuscript`，原系统提示与 Skill 不变，选定本题提供的稿件，无可检的其他库、不启动自动引用建议。Kimi Code 用指定 API provider、新会话、只读附件的 Read/Grep 工具，用实际导出核对 `llm.request` 的模型和工具记录。Kimi 拿到同一文本的纯文本形态；产品拿到 DOCX，**在调用 Luna 前逐段比较真实解析回执与文本**。这是同资料、不同阅读交互的诊断，不是正常通用 Agent 开放网络对照。该工具约束及事后审计不声称为操作系统级沙箱。
- 两侧用户指令相同：给定论文是唯一证据材料，输出 `status`、`answer`、`evidence`（段号、非空连续原样片段）。以最终回答为准，不用工具轨迹补写。在产品侧核查完成状态与 Native Responses 返回的真实模型，`store=false`；Kimi 新会话逐调用核对实际模型，无切换 DeepSeek 或其他渠道。技术包络每题 1,800 秒，另记已有递归与读取限制，不用步数或耗时给科学得分。按题配对，先手按题交错。
- 单独报告无回答、技术完成、模型身份、读材边界、格式、是否正确区分文内可答、回答分词 F1（多个参考取最大，仅诊断）、真引文、段落证据 F1 与完整覆盖。逐字证据至少含三个词，必须在所报同一段号文本中，空白、未知段号和重复不得计分；在已审段落也不代表选中的句子足以支持。对多个答案与证据组，额外报告同一条标注的最高对齐诊断，不能拼 A 标注回答和 B 标注证据。字面分与证据段指标不是科学通过或人工盲审分；以参考不可答计算的错误也是官方文本条件诊断。报告保留歧义、失败和模型不可核验。
- 运行前冻结题目、回执所需文本、提示、产品代码与测试配置、脚本和上游参考。首次失败不覆盖结果；断点恢复跳过已有结果（包括失败），有未完成的审计文件时停，不盲重试。仅测试公开材料，不触及现网、用户稿件或秘密配置。
